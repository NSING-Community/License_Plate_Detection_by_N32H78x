# RELEASE v1.0 —— 检测 + 识别两级结构（三网串联，阶段性冻结）

**冻结日期**：2026-10-16　**冻结依据**：`VERSION_CONFIRM_1.0.log`（514 张 val 全量，13 秒跑完）
**前置报告**：`NIGHT_REPORT_2026-10-15.md`（下称「报告」）
**范围**：只冻结**识别链路与权重**。检测器**不再续训**，串级结构**不再改**（理由见 §8）。

> ⚠️ **「两级」指的是两个阶段 —— 找牌 → 认字，不是两个模型。**
> 实际是**三张网串联**：① 整图找牌 → ② 裁剪找字 → ③ 逐字分类。
> ① 和 ② 结构相同、参数量相同（各 242,365），但**权重不同、输入分布不同，不能互换**。
> 早期文档和文件名里的「两模型级联」「two-stage」都指这条**三网**链路；
> 板端实现与本文口径有差异的地方，统一列在 **附录 A**。

## 0. 一句话

三个网络串起来：**整图找车牌 → 外扩 10% 裁剪 → 裁剪版模型找字符 → 逐字符抠出来送第二级识别头**。
（这里的 10% 是本文冻结的 PC 口径；板端 v1.0 在首轮之后会把外扩比例自适应到训练字距，
差异与理由见 **附录 A**。本节所有数字都来自下表这条固定 10% 的链路。）
在 514 张 val 上，**整串 78.99%**（逐个字符 93.17%），其中**部署真正在意的 7 字牌桶是 83.7%**。
比 v1.0 之前的单模型固件（整串 **约 1%**）高**两个数量级**。代价是**参数从 242,365 涨到 561,584（×2.32）**。

## 2. 它到底长什么样（三网串联）

```
                       ┌──────────────────────────────┐
  原始相机帧  ───────► │  ① 整图车牌检测器              │  320×320 入
  (任意分辨率)         │     voc-299-...270855ap       │  出：class 0 = 车牌框
                       └──────────────┬───────────────┘
                                      │ 车牌框（class 0 里取面积最大；板上 area_conf）
                                      ▼
                       ┌──────────────────────────────┐
                       │  裁剪：车牌框外扩 10% (margin) │  ★原生分辨率裁，不是先缩后裁
                       └──────────────┬───────────────┘
                                      │ 裁块
                                      ▼
                       ┌──────────────────────────────┐
                       │  ② 裁剪版字符检测器            │  320×320 入
                       │     voc_crop_ft-119-...589619 │  出：class 1..69 = 单个字符
                       └──────────────┬───────────────┘
                                      │ 字符框（class > 0，分数序前 16，cap 7，按 x1 排）
                                      ▼
                       ┌──────────────────────────────┐
                       │  逐字符抠：外扩 25% (pad 0.25) │  ★在裁块的原生分辨率上抠
                       │  → resize 32×64               │
                       └──────────────┬───────────────┘
                                      │ 每个字符一条 32×64 的小图
                                      ▼
                       ┌──────────────────────────────┐
                       │  ③ 第二级字符识别头            │  32×64 入 → 70 类 argmax
                       │     charhead_16_32_64_32_64   │
                       └──────────────┬───────────────┘
                                      │ 逐字符的类别
                                      ▼
                       按 x1 升序拼接 → GBK 字节截断到 12 字节 → 输出串
```

**注意 ① 和 ② 是两个不同的网络，虽然结构完全一样、参数量完全相同。**
① 看的是**整张图**（学的是「车牌长什么样」），② 看的是**裁出来的车牌块**（学的是「字符长什么样」）。
两者不能互换 —— 报告 §1.4 记录了整图模型直接当字符识别器用时整串只有约 1%。

## 3. 权重清单与参数量

`_release_params.py` 可复现（口径见下方 ⚠️）。

| 角色 | 权重文件 | 输入 | 可训练参数 |
|---|---|---|---|
| ① 整图车牌检测器 | `weights/voc-299-epoch-0.270855ap-model.pth` | 320×320×3 | **242,365** |
| ② 裁剪版字符检测器 | `weights/voc_crop_ft-119-epoch-0.589619ap-model.pth` | 320×320×3 | **242,365** |
| ③ 第二级字符头 | `weights/charhead_16_32_64_32_64.pt` | 32×64×3 | **76,854** |
| | | **合计** | **561,584** |

- 相对单个检测器 **×2.317**。
- ③ 的权重是 dict：`state_dict` / `classes=70` / `size_wh=(32,64)` / `pad=0.25` / `c=[16,32,64]`。
  读的时候要 `torch.load(..., weights_only=False)`（里面存了 numpy 类型）。
  结构类 `SmallCharNet` 在 [train_char_head.py](train_char_head.py)。
- ⚠️ **参数量一律用 `sum(p.numel() for p in model.parameters())`**，
  **不要** `sum(state_dict.values())` —— 后者会把 BN 的 `running_mean`/`running_var`/
  `num_batches_tracked` 也算进去，检测器会多出 6,205 个（`×2.32` 会算成 `×2.37`）。
  这个坑踩过一次，见 memory `torchsummary-param-count-trap`。

### 3.1 这三个权重是怎么训出来的（补记 2026-10-21）

本文其余部分是**从权重开始的**，假设手上有这三个文件。这一段补「它们从哪来」，命令可直接跑
（环境见 §10，工作目录 `training/`；训练脚本开头会自己 `chdir` 到 `training/`）。

**数据**：`data/` 是整图标注（class 0 = 车牌，1..34 数字字母，35..69 省份）；`data_crop/` 由它派生：

```powershell
python make_plate_crops.py                              # 车牌框四周各外扩 10%，裁到原生分辨率
python genanchors.py --traintxt ./data_crop/train.txt --input_width 320 --input_height 320
                                                        # 重聚 6 个 anchor → anchors6.txt（默认 352，必须显式给 320）
```

重跑 `genanchors.py` 只是复现过程：它的初始中心是 `random.randrange` 取的，同样输入跑出来
会和手上这份差零点几像素（实测 320 下重聚 `14.67,117.94 …` vs 配置里的 `14.51,118.69 …`）。
**训练读的是 `voc.data` 里写死的那 6 个值，不是 `anchors6.txt`** —— 别拿重聚结果去改配置。

**① 整图检测器** `voc-299-epoch-0.270855ap-model.pth`：在 `data/voc.data`（epochs 300、
lr 1e-3、steps 150/250、pre_weights=None 从头训）上训到最后一轮：

```powershell
python train.py --data data/voc.data
```

存盘名规则是 `weights/<model_name>-<epoch>-epoch-<AP>ap-model.pth`（每 10 轮 + 最后一轮各存一次），
这里 `model_name=voc`，交付的是 ep299。

**② 裁剪版检测器** `voc_crop_ft-119-epoch-0.589619ap-model.pth`：**不是从头训**，是拿 ep90 续训。
配方就是一个配置文件 [`data_crop/voc_finetune.data`](data_crop/voc_finetune.data)：
`pre_weights=weights/voc_crop-90-epoch-0.477014ap-model.pth`、`epochs=120`、`steps=60,100`
（两个 LR 台阶）、`learning_rate=5e-4`、batch 128、anchor 用上面重聚的那 6 个。

```powershell
python train.py --data data_crop/voc_finetune.data
```

`model_name=voc_crop_ft` ⇒ 存成 `voc_crop_ft-<ep>-epoch-<AP>ap-model.pth`，交付 ep119。
逐轮 AP 表与「ft60 就收敛」的判据在 `NIGHT_REPORT_2026-10-15.md` §七（日志 `train_crop_ft.log`）。

**③ 字符头** `charhead_16_32_64_32_64.pt`：真值字符框抠图（外扩 25%）→ 缩到 32×64 →
`SmallCharNet(16,32,64)` 训 12 轮：

```powershell
python train_char_head.py --epochs 12                   # 默认扫 8:16:32 / 16:32:64 / 32:64:128 三档
python train_char_head.py --epochs 12 --sweep 16:32:64  # 只重跑交付的这一档
```

默认 `--data data_crop/voc.data`、`--size 32x64`、`--pad 0.25`、`--lr 2e-3`、`--batch 256`；
文件名由宽度和尺寸拼出来（`charhead_<c1>_<c2>_<c3>_<W>_<H>.pt`）。32:64:128 那档当年故意没跑完
（约 2.75 小时，而 16:32:64 离探针只剩 1.55 个点），见报告 §2.4。
交付文件里的 `val_acc=98.887`、`per_pos['0']=95.136` 与报告 §2.4 的 ep12 那一行逐位对得上，
可以拿来核身份。

⚠️ 这两个 `.pt` 是**改脚本之前**存的：`val_acc`/`per_pos` 里是 numpy 标量，
`torch ≥ 2.6` 默认 `weights_only=True` 会直接 `UnpicklingError`。读它们要显式
`weights_only=False`（同 §3 第 2 条）。脚本现在已改成存纯 python 类型，重训不会再踩。

**算力**（报告 §9，`_flops.py`，MACs 只数 Conv2d + Linear）：

| 环节 | 相对算力 | 相对参数 |
|---|---|---|
| ① + ② （两个检测器） | 2.000 | 2.000 |
| ③ 第二级 16:32:64 | +0.226 | +0.317 |

每帧三网总成本相当于 **2.226 个检测器前向**（③ 只占其中 10%）。

## 4. 推理链路规格（逐步）

每一步的输入输出都写死在这里，固件实现照抄即可。

| 步 | 操作 | 输入 | 输出 | 备注 |
|---|---|---|---|---|
| 1 | resize | 相机帧 | 320×320×3 | `INTER_LINEAR`，`/255`，**不做 letterbox** |
| 2 | ①前向 + 解码 + NMS | 320×320 | 若干框 | 用**固件自己的** `decode` + `nms()` |
| 3 | 选车牌框 | 框集合 | **1 个**框（class 0） | PC 冻结口径：取 class 0 里 **面积最大**的（等于训练期 `make_plate_crops.best_plate`；**不是** score 最高 —— 早期文档这里写错了）。**板端 v1.0 用 `area_conf`**：分数在最高分 0.20 内的框里再取面积最大，见附录 A.1；没有就整帧失败 |
| 4 | 裁剪 | 原图 + 车牌框 | 裁块 | **外扩 10%（`margin=0.10`），在原生分辨率上裁**。板端首轮同此，之后自适应，见附录 A.2 |
| 5 | resize | 裁块 | 320×320×3 | 同步 1 |
| 6 | ②前向 + 解码 + NMS | 320×320 | 若干框 | 同固件后处理，conf 0.10 / NMS 0.30 |
| 7 | 挑字符框 | 框集合 | ≤16 个框 | PC 冻结口径：分数序取前 16 个 `class_id > 0`。**板端 v1.0**：NMS 后候选先按分数留前 64（`YOLO_CROP_MAXBOX`，`keep_top=1`），再 cap 7，见附录 A.3 |
| 8 | （可选）cap | ≤16 个框 | ≤N 个框 | 按分数砍到 N —— **板端 v1.0 已实现 cap 7**（`YOLO_CHAR_MAX`），PC 侧用 `--maxchars 7`，见 §5.2 #3 |
| 9 | 排序 | 框集合 | 按 **x1 升序** | ★ 不是按分数！分数序拼出来是乱的 |
| 10 | 逐框抠图 | 原图 + 框 | 每框一张小图 | **框坐标从 320 空间按 `sx, sy` 还原到原生分辨率**再抠；**外扩 25%（`pad=0.25`）** |
| 11 | resize | 小图 | 32×64×3 | `INTER_LINEAR`，`/255`；出界部分按 0 填（`clip` 到图边界） |
| 12 | ③前向 | N×(32×64×3) | N 个类别 | 全 70 类 `argmax(1)`，**不做 softmax / 不做拒绝**。**板端 v1.0**：位次可信的 7 字行按位限定类别范围（位 0 省份 35..69、位 1 字母 11..34、位 2..6 数字字母 1..34），见附录 A.4 |
| 13 | 拼接 | N 个字符 | 串 | 按 x1 序，**GBK 字节**截断到 12（`YOLO_PLATE_MAXLEN`） |

**★ 步 4 和步 10 是全篇最容易做错的两步**，理由见 §7。

⚠️ **步 12 没有「拒识」** —— 第二级对每个框都硬输出一个类别。
如果某个框其实是误检，它也会变成一个字符插进串里。这是 §8 里那部分残余错误的一个来源，
但**实测加拒识不划算**：报告 §3.9 量过，top-3 只比 top-1 高 0.67 点，信息量已经用尽了。

## 5. 固件常数与需要的改动

### 5.1 每一级的 conf / NMS / cap

**PC 冻结口径**（本文所有数字都是这条链路量的）：

| 级 | conf | NMS | 框数 |
|---|---|---|---|
| ① 找车牌 | `0.25` | `0.45` | 全部 class 0 |
| ② 找字符 | `0.10` | `0.30` | 分数序前 16 个，再 `--maxchars 7`（cap） |

**板端 v1.0**（`mcu_code/Printf2/inc/yolo_inference.h`）—— 两级各一套宏，互不影响：

| 宏 | 值 | 归属 |
|---|---|---|
| `YOLO_CONF_THRESH` / `YOLO_NMS_THRESH` | `0.25f` / `0.45f` | ① 找车牌 |
| `YOLO_CROP_CONF` / `YOLO_CROP_NMS` | `0.10f` / `0.30f` | ② 找字符 |
| `YOLO_CROP_MAXBOX` | `64`，满了按**分数**留 top-64 | ② 候选上限 |
| `YOLO_CHAR_MAX` | `7`（cap 到 7） | ②→③ |
| `YOLO_PLATE_MAXLEN` | `12`（GBK 字节截断） | 输出串 |
| `YOLO_GRID0 / GRID1` | `20 / 10` | 三个检测头的网格，结构没变 |

> `YOLO_PLATE_MAXBOX 16` 现在只是 `yolo_inference.cpp` 里**单模型老路径**的局部常量，
> 不属于级联；级联的框数上限是 `YOLO_CROP_MAXBOX` + `YOLO_CHAR_MAX`。

**⚠️ 5.1 这两套 conf/NMS 的分工不能混：`0.10 / 0.30` 是给②（字符检测）的。①（找车牌）不要跟着降。**
报告 §3.7 实测（`full_pipe_pred_c10.log`，车牌 conf 0.10 / NMS 0.30）：
**检出张数一个没多 —— 496 → 496（96.50% 不变）**，
而端到端反而从 **78.99% 掉到 77.04%**（同一次对照里 IoU 中位 0.893 vs 0.892，也没变好）。
⇒ **① 保持 `0.25 / 0.45`；降它只赔不赚。**
（⚠️ 那组对照的裁剪版模型是 `voc_crop-90`，不是本版本的 ft119，所以绝对数偏低；
**结论只看方向：车牌门限不是漏检的解药。**）

### 5.2 需要新增的改动

| # | 改动 | 必要性 | 收益 |
|---|---|---|---|
| 1 | **第二级字符头**：新增网络 + 步 10–13 的抠图/前向/拼接 | **必需** | 整串 26.85% → 81.84%（同一批框，`VERSION_CONFIRM_1.0.log`） |
| 2 | **①→② 裁剪**：车牌框外扩 10%、原生分辨率裁、再 resize | **必需** | 不做这一步两级串不起来；外扩比例是**契约**，见 §7 |
| 3 | **cap 到 7**：步 8，NMS 之后按分数砍到 7 个框 | 建议 | **+0.97 点**（78.02% → 78.99%，5 张图） |
| 4 | 几何过滤 `yolo_plate_geo_set()` | **保持关闭** | 本版本的确认数字都是关闭状态下量的 |

**关于 #3 —— 这一步要按真实车牌长度设，不是越紧越好。**

- 本数据集 train 侧：7 字 **4,366** 张、8 字 **84** 张 ⇒ cap = **7**。
- 报告里量过：**cap 到 6 直接把整串打到 0.97%**。
- ⚠️ **绿牌（新能源 8 字）如果在业务范围内，就要 cap 到 8**，那点收益会缩水。
  **这是个业务问题，不是模型问题 —— 部署前必须确认。**

**cap 7 vs cap 8 现在有实测了**（`val_area_conf_7.log` / `val_area_conf_8.log`，514 张 val，
ft119，① 0.25/0.45，② 0.10/0.30）：

| maxchars | ② 逐字 | ② 整串 | 位0 | 位1–6 |
|---|---|---|---|---|
| **7（冻结值）** | **93.32%** | **79.18%** | 88.52% | 89.45% |
| 8 | 91.57% | 78.21% | 88.72% | 87.50% |
| 不设限 | 91.67% | 78.21% | 88.91% | 87.63% |

⇒ **放宽到 8 要付 1.75 点逐字 / 0.97 点整串**（val 是 7 字主导，第 8 个框几乎总是噪声）。
所以 cap 7 **不是缺陷、是这个分布下的最优**；绿牌要的是**按长度分支**（绿牌 → 8，蓝牌 → 7），
不是把全局 cap 调大。别直接改 8。

**关于 #4** —— `yolo_plate_geo_filter()` 是一段「只删不加」的过滤（`yolo_inference.cpp:275`），
默认关闭。本版本所有确认数字都是**关闭**状态下量的，**先别开**。
它是否值得开，报告里在低 conf 下量到过 ±0.2 点的小摆动（噪声内），**没有结论**。

### 5.3 不需要改的

- `YOLO_PLATE_MAXBOX` 的截断、`nms()` 的类无关贪心、`yolo_plate_read()` 的排序规则
  —— **全部保留原样**。第二级是接在**它们的输出**后面，不是替换它们。
  （② 自己那一路的候选上限是 `YOLO_CROP_MAXBOX`，2026-10-20 起按分数留 top-64，
  与这里的单模型老路径无关，见附录 A.3。）

## 6. 确认过的数字

**唯一权威日志：`VERSION_CONFIRM_1.0.log`**（514 张 val 全量，13 秒）。
配置：① 预测车牌框，margin 0.10，车牌 conf 0.25 / NMS 0.45；② conf 0.10 / NMS 0.30。

### 6.1 链路各环节

| 环节 | 数字 | 来源 |
|---|---|---|
| 车牌检出 | **496 / 514 = 96.50%** | 同日志 |
| 车牌框 IoU | 中位 **0.892** / 均 0.860 | 同日志 |
| 拼串长度正确 | 88.7%（cap 7） | 同日志 |

### 6.2 端到端（★ 落地数字）

| 配置 | 逐字 | **整串** | 位 0 | 位 1–6 |
|---|---|---|---|---|

## 7. 部署硬约束（这几条是契约，不是建议）

### 7.1 裁剪外扩 10%，且必须在原生分辨率上裁

- **外扩比例**：`margin = 0.10`。报告实测**裁紧掉 16.5 个点**（字符更大反而更差）——
  模型是在外扩 10% 的取景上训的，**改取景 = 换分布**。见 memory `plate-crop-margin-contract`。
- **板端 v1.0 的例外**：板端 ① 的框比训练 GT 紧，同一个 10% 在板上会把字放大到
  pitch 29~36（训练 p50 是 25.8），超出 ② 的 anchor。所以板端**首轮用 10%**，
  之后用 ② 自己量到的字距把外扩比例收敛到「字距 = 25.8」，夹在 `[0.02, 0.70]`。
  这不是改契约，而是**把取景拉回训练分布**的闭环，见附录 A.2。
- **顺序**：先按**原图**裁车牌块，**再** resize 到 320×320。
  反过来（先 resize 整图再裁）等于把字符又缩回 13px，第二级就白搭了。

### 7.2 字符抠图外扩 25%，同样在原生分辨率上抠

- `pad = 0.25`，和第二级训练时一致，**改不得**。
- 字符框是在 320×320 空间里预测的，抠图前**必须按 `sx, sy` 还原到原生坐标**
  （`two_stage_e2e.py:247-251` 这段注释就是为这个写的坑）。

### 7.3 拼串按 **x1 升序**，不是按分数

`nms()` 的输出是分数序。直接用分数序拼串得到的是乱码。
`yolo_plate_read()` 里已经有这一步（`idx.sort(... x1 ...)`），**保持不动**。

### 7.4 加第二级之后，`①` 的角色变成「只找车牌」

不要再拿「① 的 class argmax」当识别结果 —— 那一列在 cap 7 下只有 26.85%，
**它已经从识别器降级成定位器了**。任何「① 读得还行」的印象都是旧口径。

### 7.5 门限常数只能整体调，不能只调一个

`conf 0.10` 和 `NMS 0.30` 是**成对**选的。报告 §3.5 量过 `conf 0.10 / NMS 0.45`：
位 0 有 92.80%，整串却只有 60.12% —— **NMS 放松后多出来的框会把串挤错位**。

## 8. 已知边界与未解决的问题

### 8.1 框数 / 框质量的天花板（**已确认无余量**）

报告 §3.9 的闭环账（`_char_box_quality.py`）：

| 口径 | 逐字 |
|---|---|
| ③ 在**真值**字符框上 | **99.08%** ← 识别头已经做完了 |
| ③ 在**预测**字符框上（真机） | **97.00%** |
| ⇒ 框质量净代价 | 2.08 个逐字点 ≈ 7 字整串 **8 点** |

**坏框只有一个方向：太宽**（IoU<0.7 占 5.31%）。**拆裂 0 个，合并 30.9%。**
宽比 ≥1.3 的字符（3.2%）二级逐字从 98.8% 崩到 59.0%。

**两条先入为主的怀疑都被实测否掉了**：不是糊图（清晰度皮尔逊 **0.012**）、
不是 anchor 先验（best-IoU **0.9025**）。**病根是网格分辨率**：
320 空间里字符 24px 宽、pitch 45.7px，而 **stride-16 的格子就是 16px —— 一个字符 1.5 格**，
且 **98.8% 的框由这一层产出**。

⚠️ **唯一的修法是给②加 stride-8 头，但那条路没有被实测过** ——
只证明了「瓶颈在分辨率」，**没证明「加一层就能修」**。
所以它**不进这个版本**。要做的话，报告 §8 rec 6 写好了第一步：
**先训新头、量「预测框逐字」这个数（现 97.00%），涨了才动固件解码器。**

### 8.2 3.5% 的车牌漏检 —— 这是全链路唯一的硬缺口

18/514 张图**根本没裁到车牌**，在整串率里按全错计。
报告实测：**降车牌门限救不回**（§5.1）。⇒ 96.50% 的检出率是链路当前的硬上限。

### 8.3 val 本身有偏差，所有 val 数字都带这个偏差

报告 §3.8（`_split_compare.py` / `_split_chars.py`）：

- val 是**按文件名连续切块**（`4459–4979`），**不是随机划分**；
- **6 字牌富集 27 倍**（3.50% vs train 0.13%），且那 18 张是**真值标错**；
- **字符组成是另一个子 population**：`澳 / 港 / 新` 在 val 里**一个都没有**，
  `J/M/N/R/S/Y` 富集 1.5–2.4×，`B/C/D/E/F/K/Q` **只剩一半**。

⇒ **「78.99%」不是一个无偏估计。** 连按串长重加权也只修了一半。
**而且这个 val 同时还被我用来挑常数**（conf / NMS / cap）——
**要在 k−1 折上挑、第 k 折上报，别在同一份数据上两头都占。**（下次要做的事。）

### 8.4 第二级没有拒识

见 §4 步 12。误检框会变成字符。**实测加拒识不划算**（top-3 只高 0.67 点）。

### 8.5 步 3 的挑框规则：**面积最大在域外会挑错**（建议随 v1.0.1 一起改）

`pick_plate` 取「class 0 里**面积最大**」（= 训练期 `best_plate` 的规则，val 96.50% 就是这么算的）。
**它在同分布 val 上没问题，但在陌生相机/场景里会挑到地面上的大片误检**：

- `img/09.jpg`：真牌 **score 0.993 / 面积 7794**，地面误检 **0.378 / 10222** ⇒ 选了地面。
- `img/06.jpg`：真牌 **1.000 / 9127**，地面误检 **0.145 / 12929** ⇒ 选了地面。

**补丁：`--plate-pick area_conf`** —— 先扔掉比最高分低 `conf_margin`(默认 0.20) 以上的框，再取面积最大
（`full_pipeline_e2e.pick_plate`）。**在 val 上每一列都不亏**：

| 规则 | ② 逐字 | ② 整串 | 位0 | 位1–6 | 检出 |
|---|---|---|---|---|---|
| `area`（v1.0 冻结值） | 93.17% | 78.99% | 88.33% | 89.32% | 496/514 |
| **`area_conf`** | **93.32%** | **79.18%** | 88.52% | **89.45%** | 496/514 |

+0.19 点 = **1 张图 = 噪声地板内**（§6.4），所以这不是「val 上的提升」；
但它在 `img/` 上**确实修好了上面那 2 张**（09 从「陕皖陕1赣」变成「B2112」且框落到真牌上）。
**判为「不亏的加固」，推荐 v1.0.1 采纳；v1.0 的冻结数字仍按 `area` 记。**

## 附录 A —— 板端 v1.0 的实际实现（与本文 PC 口径的差异）

**必读。** 本文冻结的是 **PC 链路**，§0–§11 的数字全部由它量出。板端为了在
真实相机帧上跑稳，在几个地方**多做了 PC 上没有的处理**。它们**没有参与 78.99% 的测量**，
所以板端日志里的读数不能直接和本文的数字互推；逐项差异如下（实现位置都在
`mcu_code/Printf2/MDK-ARM/yolo_inference.cpp`）。

**A.1 选牌框：`area` → `area_conf`**
- PC 冻结：`pick_plate(rule="area")`，class 0 里取面积最大（本文步 3）。
- 板端：`pick_plate_area_conf()` —— 先取分数最高的框，再在**分数 ≥ 最高分 − 0.20**
  （`YOLO_PLATE_PICK_MARGIN`）的 class 0 框里取面积最大。
- 理由：域外的误检框往往「又大、分又低」，纯面积会挑错牌；val 上 `area_conf` 不亏，
  且修好了 09/06 那两张。见 memory `plate-pick-area-fails-out-of-domain`。

**A.2 裁剪外扩：固定 10% → 自适应到训练字距**
- 首轮用 `YOLO_CROP_MARGIN = 0.10`（训练契约）。
- 之后用上一轮 ② 量到的 pitch 反推需要的裁剪宽，比例夹在
  `[YOLO_VIEW_MINM, YOLO_VIEW_MAXM] = [0.02, 0.70]`，每轮朝目标走 50%
  （`YOLO_VIEW_MIX`）；目标 pitch = `YOLO_VIEW_PITCH = 25.8`（训练 p50）。
- 为什么：板上 ① 的框比训练 GT 紧约 20%，同一个 10% 会把字放大到 pitch 29~36，
  超出 ② 的最大 anchor（27.7 宽），框只能顶着上限回归。下限 0.02 是为了让远处的
  小牌也能达到 pitch 25.8（夹在 0.10 时远牌卡在 18.7，末两位粘连、省字位每轮翻）。
- 见 memory `crop-framing-contract`、`crop-resolution-effect-2026-10-15`。

**A.3 ② 的候选上限：光栅序截断 → 按分数留 top-64**
- `keep_top=1`：NMS 后候选超过 `YOLO_CROP_MAXBOX = 64` 时按**分数**保留前 64，
  再按分数 cap 7（`YOLO_CHAR_MAX`），最后按 x1 排序。
- 旧实现是光栅序截断（图的上半部分先占满名额），与 PC 的「`fw_decode` 光栅序 64 →
  按分数取 16 → cap 7」**静默不一致**；2026-10-20 现场 161 轮里有 109 轮候选摸到 64，
  一直在生效。

**A.4 ③ 的分类：全 70 类 → 按位限定**
- 位次可信的 7 字行按车牌语法限定每一类的 argmax 范围：
  位 0 只认 35..69（省份字）、位 1 只认 11..34（字母）、位 2..6 只认 1..34（数字/字母）。
- 位次不可信（非 7 字 / snap 判定位次错位）时退回全 70 类 argmax，与本文步 12 一致。
  仍然**不做拒绝**。

**A.5 7 字几何：格点、补位、宽度归一**
- 格点间距不是等距：`i + 0.357*[i>=2]`（0.357 是从训练标签量出来的隔离点间隔）。
- n=6 时按相对判据（`r_uniform ≥ 0.10` 且 `r7 ≤ 0.4·r_u`）把末两位粘连的框补成 7 个；
  **不要再放宽**，中间漏位时补出来是错的（memory `n6-last-char-merge`）。
- 宽度**无条件**归一到行中位数；中心投影只在整行位次可信时做
  （memory `char-box-jump-separator-dot`）。

**A.6 横滚去斜**
- 倾斜超过 0.46° 时，沿**牌面自己的两个轴**重采样（`resample_aff_to_i8`），把字行转正；
  小于门限仍走普通矩形缩放，竖直牌逐像素等于冻结基线。
- 角度是从 ② 的输出量出来的**残差**，必须累加到"本轮已用角度"上；单轮增量有闸
  （防止一次坏框把 20° 误差推进积分器并正反馈），总角度夹在 17°。
  见 memory `plate-roll-deskew`、`roll-integrator-needs-gate`。

**A.7 ① 的帧间复用**
- 板端每 `YOLO_PLATE_REUSE_AGE = 5` 轮才重跑一次 ①（② 掉框时提前作废）。
- PC 上 ① 每帧都跑。复用是**纯板端机制**，不改变单轮链路，只改变节奏与算力。

**A.8 输入通道序**
- 板子相机喂的是 **RGB**，训练全程是 **BGR**。实测整串 −1.85 点、位 0 −6 点。
